# Synchronized Implementation Plan

**Project:** Risk Monitoring for LLM Trading Agents
**Last synchronized:** 2026-11-16
**Purpose:** One source of truth for the simulation environment and the experiments that use it.

This document supersedes conflicting run matrices and status statements in older design notes. Historical calibration reports remain records of what was run at the time; they are not evidence that the final environment has passed its acceptance criteria.

## 1. Research question and causal comparison

### Primary Phase 1 question

> In a fixed-size, calibrated perpetual-futures market with a fixed distribution of trading roles, how does replacing scripted decision-makers with LLM decision-makers change market quality and systemic risk?

The primary intervention is **decision-maker type within a role**, not population size. The primary population is 100 trader accounts, with 0%, 25%, 50%, 75%, or 100% LLM-controlled accounts. The exact population, role counts, capital allocation, leverage policy, scenario path, and execution rules must be the same across conditions. At a given scenario and environment seed, all conditions use the same exogenous reference-price path and the same pre-registered random streams where applicable.

The separate density question—how risk changes with total trader count—is secondary. It varies total population only after the fixed-100 replacement experiment is implemented and analyzed. A density comparison must state whether total market capital and liquidity scale with population; it cannot silently change both population and aggregate capital.

### Causal estimand and scope

The primary estimate is the paired difference in outcomes between a scripted trader and an LLM trader **assigned to the same role slot**, aggregated over the fixed market population and repeated market paths. It estimates the effect of the decision policy under this simulated environment, not the effect of real-world human traders or all possible LLM trading systems.

Population replacement also changes the collective behavior generated by the new decision policy. That collective response is part of the treatment effect; it is not an uncontrolled confound. Differences in role mix, capital, leverage, market rules, or exogenous paths are confounds and must be controlled.

## 2. Agent heterogeneity design

Do not use one generic prompt for every LLM, and do not create a unique untracked prompt for every agent.

### Core role-stratified design

1. Define a small, pre-registered set of roles that has a meaningful scripted counterpart, for example momentum/trend, value/mean-reversion, contrarian, and market-making. Treat the current `CrowdBot` separately: it deliberately creates crowded leveraged longs and is a stress-mechanism bot, not a neutral or ordinary-trader proxy.
2. Give each role one versioned prompt template, a fixed action schema, and explicit risk constraints. Agent-specific state (account balance, position, order history if modeled) is supplied as data, not embedded as an untracked prompt variation.
3. Build the 100 account slots from a documented role mix. For the main comparison, each role slot is assigned either its scripted policy or its role-matched LLM policy. At each LLM share, sample replacements within every role using a recorded random seed; preserve the role proportions as closely as integer counts allow.
4. Keep provider, model snapshot, system prompt version, temperature, token limits, timeout policy, parsing rules, and fallback behavior fixed and logged for a confirmatory run.
5. Run prompt/model diversity as a separate sensitivity experiment. Do not mix it into the primary estimate.

This allows the primary comparison to ask whether the LLM implementation changes decisions within a given behavioral role. It does not assume that the scripted rules perfectly represent human traders. Report the strategy-role distribution as an explicit modeling assumption.

### Phase 0 populations are tools, not the Phase 1 population

- The interactive demo uses **13 bots**: 4 Crowd, 4 Trend, 2 Contrarian, 2 Value, 1 Maker. The fractions are 30.8%, 30.8%, 15.4%, 15.4%, and 7.7%. It is a compact demonstration population, not a scaled-down calibration sample.
- The calibration scripts use **50 bots**: 20 Crowd, 10 Trend, 7 Contrarian, 7 Value, 6 Maker. The realized fractions are 40%, 20%, 14%, 14%, and 12%; integer rounding explains why the last three differ from the nominal 15%, 15%, and 10% targets.
- These mixes must not be compared as if bot count were the only difference. Calibration runs must save population counts and strategy settings with each result.
- The main Phase 1 candidate should **exclude CrowdBot**. Its 40% share in the current 50-bot calibration exists because calibration population was designed to create a crowded-long stress mechanism; carrying that share into a neutral decision-maker comparison would pre-load the market with the risk under study. Keep CrowdBot for a later, separate sensitivity arm that asks whether an intentionally crowded population amplifies LLM effects.
- To provide an implementable Phase 1 starting roster while acknowledging that there is no evidence for a “real trader” role mix, use the four non-Crowd proportions from the 50-bot calibration, renormalized: Trend 10, Contrarian 7, Value 7, Maker 6 (30 total) becomes **Trend 34, Contrarian 23, Value 23, Maker 20 (100 total)** using largest-remainder rounding. This is a provisional controlled mix, not a claim about actual market prevalence. Use it for the Phase 1-scale environment build and parameter checks, then freeze it before confirmatory runs; test alternative mixes separately.
- The LLM role templates should correspond to Trend, Contrarian, Value, and Maker roles. For every LLM share, replace agents within these same role slots; do not ask all LLMs to follow one generic prompt. The scripted rule defines the comparison role, not a claim that the LLM must behave identically to that rule.

### Liquidity parameters are related and need joint sensitivity checks

The scenario currently supplies nominal background depth of **8 BTC per side** in thick conditions and **4 BTC per side** in thin conditions. This is total size across the five quote levels on each side, not the depth measured inside the configured 0.5% observation band and not executable liquidity guaranteed to remain available. With five equal levels, nominal size starts at about 1.6 BTC or 0.8 BTC per level before rounding and stress retreat.

The configured `bg_level_gap=0.003` spaces adjacent levels by 0.3%. With five levels and the current offset formula, the outer level is about 1.2% from the quote centre (plus the half-spread), not 1.5%. `depth_band=0.001` now measures orders within 0.1% of the book mid to match the checked-in Bybit near-depth definition; it will not count all five levels.

Depth, quote spacing, half-spread, anchor strength, and stress retreat work together: more near-price size and a stronger anchor generally absorb trades and pull quotes toward the outside reference; wider spacing or withdrawn size can increase price impact. Do not select arbitrary example values as requirements. First use the empirical order-book distribution to set a representative scale and ladder shape; then test a predeclared uncertainty band around that evidence. Preserve empirical bid/ask depth percentiles and the ratio of trader order flow to executable depth when scaling to the Phase 1 population. Check depth at several price bands, effective spread after tick rounding, price impact, liquidity recovery, liquidations, and a no-liquidation mechanism check. The objective is a documented data-based choice with robustness bounds, not a cascade-producing value.

### Phase 0 to Phase 1: calibrate the target environment, then use a smaller build population

Phase 0 must define the Phase 1 account/economic rules early, rather than postpone them. Freeze the intended 100-slot role roster, per-account capital distribution, leverage/margin schedule, order limits, and Phase 1 market clock as the **target design** before final calibration. Then use 50 scripted agents as a cheaper development population that exercises the same account rules and strategy roles. Do not automatically halve or double background depth: scale it using the empirical ratio of trader order flow/notional to near-book liquidity, and report which market statistics do not scale linearly.

Use a practical two-pass process:

1. **Market-data target fitting:** fit only quantities that can be measured from real data (reference returns, trade activity, spread, depth curve, funding distribution, order-flow behavior), using a training period. Do not include an engineered one-off shock in ordinary-market fit statistics.
2. **Mechanism calibration in the 50-agent minimarket:** use the Crowd-excluded Phase 1 role mix scaled to 50 (Trend 17, Contrarian 12, Value 11, Maker 10) with the Phase 1 per-account rules to tune the simulator’s endogenous market response, especially trade impact and liquidity recovery, against observed data. Keep the legacy 20-Crowd population as a separately labeled mechanism stress/sensitivity run, not as the sole calibration population. Record unavoidable scale differences.
3. **100-slot portability check:** run the candidate 100-slot Phase 1 population with the same per-account economics and verify that the market remains in the intended measurable regime. If it differs, adjust the environment using the empirical scaling rule and rerun both sizes.
4. **Freeze:** select the Phase 1 environment parameters and role mix before LLM treatment outcomes are examined. No fitting to the preferred LLM result.

The old 50-account `$50,000` budget is not automatically the Phase 1 budget. If the 100-slot candidate also uses `$1,000` per account, its total is `$100,000`; if total capital is instead fixed at `$50,000`, each slot receives `$500`. Choose one economic interpretation and hold it constant across every replacement share. To separate per-trader policy effects from market-scale effects, the default recommendation is fixed per-account economics for the fixed-100 primary study; test any different aggregate-capital scaling as a separate robustness condition.

### What “scripted-policy control” means

The 0% LLM condition contains only the project’s declared rule-based strategies in the fixed role slots. It is called a scripted-policy control because it controls the market setup while specifying a known decision rule. It is **not** 100 sampled human “normal traders”: no human data generated these rules or established their population proportions. The causal result is “LLM policies versus these scripted policies in this simulated market,” not “LLMs versus ordinary people in the real market.”

### Background liquidity and systemic-risk scope

The current background provider is the buyer/seller resting on the other side of trader orders. It submits buy limits below its quote centre and sell limits above it; aggressive trader orders consume those resting quantities, and price impact depends on how much is available at each level. In stress scenarios, it now retreats when either the local last-trade price or the external index moves beyond the five-step threshold. This is an observable-volatility proxy, not an inventory or solvency model; the threshold and retreat amount still require empirical calibration. The provider’s special account does not undergo margin checks, which keeps the quote ladder available as a controlled liquidity source. This does **not** disable trader liquidations: every normal trader account is checked against maintenance margin and can be force-closed; forced orders consume the background and other resting orders and can move the mark price, potentially triggering further trader liquidations.

This design can measure liquidation cascades among trader accounts and liquidity-shortfall/price-impact risk. It cannot measure background-provider insolvency or a closed-system default cascade. Before Phase 1, compare a resilient background-liquidity benchmark (current) with an empirically calibrated retreating-liquidity rule; later, finite provider capital/solvency can be a separate systemic-risk extension. Do not silently interpret the current infinite-solvency LP as a real exchange’s insurance fund.

### Treatment arms

- **0% LLM:** all fixed role slots use scripted policies; this is the model-based control, not a sample of real human traders.
- **25/50/75% LLM:** replace the same share within each role, with the assignment recorded and balanced across repetitions.
- **100% LLM:** all role slots use their corresponding LLM prompt template.

The original proposal's independent LLM-density levels `{5, 20, 50, 80, 100}` answer a different population-size question. Do not combine those levels with replacement shares and call them one factorial design.

## 3. Environment controls and capital accounting

### Required run invariants

Each run configuration must explicitly record and validate:

- number of trader accounts and role counts;
- each account's initial collateral and the **total initial trader collateral budget**;
- leverage cap and maintenance margin;
- maximum order notional/quantity and whether resting orders reserve margin;
- initial positions (zero unless an experiment explicitly says otherwise);
- initial market price, order-book state, fees, funding rule, tick and lot size;
- external liquidity schedule, depth, spread, anchor and walk-away behavior;
- scenario path identifier, seed, run length and tick duration;
- liquidation, bankruptcy/bad-debt, and funding-settlement rules.

The configured collateral budget is an initial-margin endowment, not literal circulating token supply or total market notional. Futures positions can create gross exposure much larger than collateral; matched positions are zero-sum in quantity, and the background liquidity provider is an explicitly modeled counterparty with effectively unlimited solvency. If the project claims conservation of cash or a finite market-wide money supply, that must be modeled and audited separately. Do not conflate collateral budget, gross notional, open interest, and circulating currency.

For the main replacement experiment, hold total initial trader collateral fixed across LLM shares and allocate it consistently to the role slots. If there are 100 equal-capital accounts, define the per-account amount from the budget (rather than increasing aggregate capital when N grows). The 50-bot calibration configuration is a different environment-calibration experiment and must identify its own fixed aggregate budget.

When configured, the engine enforces the initial trader-collateral budget at account creation. The budget excludes the background liquidity account; it does not cap subsequent PnL, funding transfers, or notional exposure. The generic engine default is unbounded for compatibility; calibration/experiment configs must set a finite budget explicitly.

### Simultaneous information and execution

At each tick, all agents observe the same pre-action market snapshot plus their own account state. Collect decisions before applying any trader order. The exchange then updates the exogenous price, refreshes background liquidity, shuffles and processes orders, checks liquidations, settles funding when due, and records the step. Document that all agents act on the last published tick state; do not imply they observe intratick order flow.

## 4. Realism versus experimental control

The project should prioritize **causal identification and mechanism validity first**, while requiring a minimum empirical-fidelity gate before making claims about real markets. Perfect reproduction of a real market is neither feasible nor required for a controlled agent experiment.

### What this priority preserves

- interpretable treatment contrasts under matched environments;
- repeatability and reproducibility;
- explicit leverage, funding, order-book and forced-liquidation channels;
- ability to test counterfactual interventions and generate labeled detector data.

### What it sacrifices or abstracts

- full trader population and venue-scale capital/depth;
- endogenous outside price discovery and cross-venue arbitrage;
- realistic market-maker competition, cancellations, latency, queue position, and participant-specific execution infrastructure;
- exact real-world zero-return rates, volatility distribution, spread/depth distributions, and crisis frequency;
- claims that observed effect sizes transfer directly to live venues.

Scale the market as a **representative-agent/minimarket model**: preserve and calibrate ratios such as trader notional to executable depth, trader collateral to position, and aggregate flow to available liquidity. Calibrate on separate real data; report acceptance metrics and held-out gaps. Do not tune the market to force the desired LLM result or to guarantee a cascade.

## 5. Phase plan and gates

### Phase 0 — Environment specification and audit (current)

**Goal:** make the environment a coherent, reproducible market model before Phase 1 claims.

1. Freeze a versioned environment contract: market mechanics, time convention, trader account rules, capital budget, external-liquidity model, scenario definitions, and data sources. Specify the target Phase 1 100-slot roster and per-account economics before final calibration.
2. Separate parameters into fixed environment, calibration parameters, experiment factors, and intervention controls.
3. Treat the Crowd-excluded Phase 1 role mix scaled to 50 as the main environment calibration population; keep the legacy Crowd-heavy 50 population as an explicitly separate stress/sensitivity population. Save each population definition in result metadata.
4. Fix bugs/ambiguities called out in Section 6 before treating the scenario matrix or calibration results as final.
5. Establish a quantitative calibration scorecard with in-sample fit and held-out performance. Include uncertainty over days and seeds; a positive kurtosis/ACF alone is not a calibration pass.
6. Add diagnostics for conservation/accounting, matching, funding transfers, liquidation behavior, reproducibility, and market-activity frequency.
7. Record the 13-bot demo mix and 50-bot calibration mix separately; do not treat either as the Phase 1 roster. Save exact bot counts and per-role strategy parameters in result metadata.
8. Calibrate/check the background quote ladder jointly from observed empirical depth curves: nominal side depth, number of levels, level spacing, half-spread, anchor strength, and stress walk-away threshold/factor. Do not prescribe arbitrary alternatives (e.g. 10/5 BTC or 0.5%); select a data-supported central value and a predeclared uncertainty band. Report nominal total depth separately from measured depth inside each price band.
9. Use target-venue tick size in the environment (currently set to $0.10 to match Bybit source book, not the previous $0.50); set background half-spread consistently with that tick and verify the effective spread against matched empirical data.

**Exit gate:** a deterministic smoke test and automated checks pass; each scenario changes the intended factor; calibration report shows pass/fail against predeclared tolerances; limitations and failed targets are visible.

### Phase 0.5 — Calibrate and validate the 50-scripted-bot environment

Use 50 scripted bots as the current calibration population (20 Crowd, 10 Trend, 7 Contrarian, 7 Value, 6 Maker), not as the final normal-trader control and not as evidence about LLM effects. The 13-bot demo is a separate teaching/smoke-test setup. Before final calibration, freeze the intended Phase 1 100-slot roster and account-economics rules. The primary Phase 1 candidate excludes CrowdBot; renormalize the four other calibration roles to 100 slots as Trend 34, Contrarian 23, Value 23, Maker 20. Treat this as a controlled modeling choice, not a claim about real prevalence, and test alternative mixes separately. Keep the 50-bot calibration roster and its CrowdBot mechanism stress as separate documented calibration/sensitivity populations. Preserve the existing multi-seed/data pipeline where valid, but rerun after correcting the environment and metrics. Compare both the exogenous reference process and the endogenous exchange outputs to real data; they are different objects and should not be reported as if they were the same.

Required comparisons include hourly and intraday volatility, return tails, zero-return/zero-trade frequency, volatility clustering, signed-flow autocorrelation, spread, empirical and simulated depth curves at several price bands, volume, price impact, liquidity retreat/recovery, funding distribution, and trader-liquidation behavior under stress. Select candidate quote-ladder values from observed L2 depth distributions and state the uncertainty range supported by the data; avoid arbitrary illustrative values becoming mandatory experiments. Include a no-scheduled-event synthetic condition; current normal and stress synthetic conditions both inject a scheduled price move and neither is a clean no-shock baseline. Compare the 50-bot calibration build and the target 100-slot build under the same per-account economics to verify scaling portability. Use realistic sampling intervals and distinguish a historical replay from an independent replicate.

**Exit gate:** document which properties are matched, which are not, the calibration/validation split, the market-scale assumptions, and whether the model is fit for mechanism experiments. Keep parameter fitting separate from evaluating the final agent treatment effect.

### Phase 1 — Fixed-population role-stratified replacement experiment

1. Primary population: 100 trader slots with a fixed role mix and fixed total initial collateral budget.
2. Conditions: LLM shares 0%, 25%, 50%, 75%, 100%, replacing within roles.
3. Pair runs by scenario and exogenous path/seed; repeat across independent paths and recorded agent-assignment seeds.
4. Keep all non-treatment parameters fixed. Log agent views, decisions, orders, fills, positions, leverage, collateral, LLM model/prompt metadata, latency, usage, and fallback events.
5. Outcomes: individual risk, market quality, synchronization, liquidity fragility, liquidation/cascade outcomes, bad debt, and recovery. Define primary outcomes and multiplicity handling before confirmatory runs.
6. Treat the 0% condition as a scripted-policy control, not “100 normal human traders.”
7. Run the total-population/density experiment separately if resources permit, with an explicit capital/depth scaling rule.

**Budget rule:** estimate calls before launch. If cost forces fewer runs, reduce repetitions or use a staged design without changing treatment definitions after seeing outcomes. Pilot runs are engineering checks and are not pooled with confirmatory results unless predeclared.

### Phase 2 — Intervention experiments

Use the Phase 1 environment and conditions, with interventions varied one at a time first. Keep paired scenarios and seeds. Separate immediate intervention effect from post-adaptation effect; scripted bots do not learn unless an explicit adaptation policy is added. Report risk benefit alongside liquidity, execution, and recovery costs. Implement only the interventions whose mechanics and success criteria are specified.

### Phase 3 — Detection, prediction, and transfer evaluation

1. Create labels from simulator-only state/outcomes; use only venue-observable features as model inputs.
2. Split train/validation/test by independent run seeds and scenario paths, not by randomly splitting adjacent time rows from the same run. Prevent future information leakage in rolling features and labels.
3. Evaluate across held-out simulator seeds, agent assignment/prompt settings, and scenarios. Report calibration, discrimination, lead time, false alarms, and performance by regime.
4. For real-market data, perform **external plausibility/transfer evaluation**, not causal validation of LLM effects. Real crises cannot identify whether LLMs caused them.
5. State clearly which simulated fields have real-time API equivalents and remove or proxy unavailable fields.

**Interpretation:** Phase 3 can show whether simulated warning patterns are detectable and whether signals behave plausibly on real data. It cannot establish deployment readiness or prove that real LLM traders would cause the simulated risk without external evidence.

## 6. Known issues in the current repository to resolve or track

1. **Historical replay and shock timing:** replayed paths ignore `shock_frac` and `shock_return`. Scenario names distinguish synthetic no-event, synthetic scheduled-event, and replay paths. Do not treat replay timing labels as a factor. Historical replay must be excluded from parameter fitting. The Oct 10 extreme path already influenced scenario selection, so it is an illustrative known stress case, not an untouched hold-out; select different unused dates for genuine out-of-sample validation.
2. **Open interest definition:** current `_open_interest()` sums only positive positions. For a single fully matched venue this is a one-sided gross position measure, but it should be named/documented accordingly and tested against venue conventions before detector use.
3. **Calibration and generated reports:** existing calibration artifacts were produced under earlier population/path logic. They are historical evidence, not valid results for the synchronized scenario design until regenerated.
4. **Parameter/version drift:** README, setup guide, calibration notes and proposal contain different defaults and run lengths. Update them as part of Phase 0; cite the active config and version in every run artifact.
5. **Validation statistics:** current positive stylized-fact checks do not compensate for large volatility/zero-return mismatches. Keep quantitative mismatches explicit; do not describe the environment as fully realistic. Use the new no-event synthetic condition for ordinary-market fit; do not treat scheduled-event runs as normal calibration samples.
6. **Capital budget:** the engine supports an optional initial-collateral cap, and calibration scripts set it to 50 × per-account collateral. The 100-account Phase 1 budget and role capital allocation must be specified in an experiment config before implementation.
7. **Population mixes:** demo (13) and calibration (50) role counts differ. Current calibration role counts are 20/10/7/7/6; no Phase 1 role roster has been approved.
8. **Quote ladder reach:** five levels at 0.3% spacing reach about 1.2% from the centre under current code, not the 1.5% written in stale comments. The simulator depth band is now ±0.10% to match the checked-in Bybit near-depth definition. Derive the ladder from matched empirical bands; illustrative alternatives are not prescribed values.
9. **Stress replay duration:** a replay is a fixed 600-minute event path. A 120-minute demo sees only its first two hours and may not include the most severe move; select the replay window deliberately and report it.
10. **Historical-data leakage:** the prior script replayed Oct 10 in stress grid search, and that date also influenced choosing the extreme replay path and synthetic shock magnitude. The calibration script now fits the synthetic process without scheduled events. Oct 10 is not an untouched validation sample—choose unused dates for that gate.
11. **Synthetic no-shock control:** the scenario matrix now has separate no-event synthetic, scheduled-event synthetic, and historical replay paths. 12. **Phase 1 target vs calibration population:** decide account-level capital/leverage and the 100-slot roster before final calibration. Main candidate excludes CrowdBot and uses Trend 34, Contrarian 23, Value 23, Maker 20 as a transparent normalized starting mix; sensitivity-test alternatives. 13. **Calibration status after rerun:** the first quick run incorrectly compared sparse local last trades with real-market volatility. A local-inactivity penalty is now included in the fit score; this raises the quick scores but does not solve the mismatch. The run is a diagnosis, not calibration acceptance: quick mode searches only two depth values and one seed, does not establish uncertainty, and does not match local activity/spread. 14. **Order-book depth band mismatch:** reference CSV documents Bybit near-depth as ±0.10%, while old processed targets and calibration report contents were generated under previous assumptions. The synchronized quick run reports the target label as 0.10% but does not make old aggregates valid; regenerate target/result artifacts from the corrected scripts and matching simulator band.
15. **Held-out / microstructure findings from remote `main` (reviewed 2026-11-18):** the former held-out run used a fixed 1%-6% flat-minute interval although measured frequency was about 0.56%, injected a synthetic shock into held-out dates, and scaled dials using held-out statistics before scoring those same dates; those conditions invalidate the old headline score. The local validator now uses no scheduled event, freezes training dials, compares local last-trade returns (not external index) with held-out returns, reports flat minutes descriptively, excludes dial-derived spread from independent scoring, and rejects Oct 10 or training/held-out overlap.
