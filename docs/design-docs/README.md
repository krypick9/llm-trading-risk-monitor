## Convention

Each design doc should include:
1. **Objective** — what this component does
2. **Interface** — how other components interact with it (function signatures, data formats)
3. **Dependencies** — what it needs from upstream tasks
4. **Design decisions** — why this approach, alternatives considered
5. **Open questions** — what needs team/supervisor input
